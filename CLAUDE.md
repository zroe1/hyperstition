# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Research code for a paper on **trait amplification under iterative self-training**: seed a model with a persona/belief (bliss, nvidia-pessimism, misalignment, sycophancy, lucky, hopelessness, misanthropy, medical, financial), then repeatedly fine-tune each generation on data generated by the previous one and measure whether the trait amplifies, persists, or decays. Three training regimes: SFT on instruct models, synthetic document fine-tuning (SDF, continued pretraining on base models), and DPO. All training and sampling goes through the **tinker** API (LoRA, remote); scoring uses GPT-4o (OpenAI) and OpenRouter judges. The paper source is `colm2026_conference.tex`.

There are no tests and no linter configured.

## Environment

```bash
pip install -r requirements.txt
pip install -e .            # pyproject sets package-dir to src/; required so `from training_configs import ...`, `from paths import ...` etc. resolve
export OPENAI_API_KEY=... TINKER_API_KEY=... OPENROUTER_API_KEY=...
```

All scripts are run **from the repo root** (paths like `outputs/...` and `datasets/...` are relative to it). Imports inside `src/` are top-level (`training.train_n_cycles`, `evaluation.eval`, `paths`), so either the editable install or `PYTHONPATH=src` is required. Cluster jobs in `jobs/` are SLURM scripts that `cd $HOME/hyperstition`, activate `.venv`, and `source ~/.secrets` for keys.

`outputs/`, `cache/`, `logs/`, `plots/` are gitignored. Model weights never live on disk; they are `tinker://` paths saved with a 1-week TTL (see `--tag` and `src/delete_checkpoints.py`).

## Architecture

### Configs are the unit of an experiment
`src/training_configs/<name>.py` is a plain module registered in `training_configs/__init__.py` (`EXPERIMENTS` dict, `get_config(name)`). Every trainer, sweep, eval, and plot script takes `--config` and reads attributes off the module via `getattr`, so adding a trait = adding a module with:
- `DEFAULT_DATASET` (relative to `datasets/`), `EVAL_QUESTIONS`, `SCORE_PROMPT` (or legacy `ALIGNMENT_PROMPT`) with `{question}`/`{answer}` placeholders, and `QUERIES_FILE` (relative to `src/data/`, prompts used to generate cycle 1+ data).
- Optional: `TEST_DATASET`, `PERPLEXITY_DATASETS` (high/low buckets), `SDF_SCORE_PROMPT` + `SDF_EVAL_PREFIXES` (for base-model/SDF evals).
- `COHERENCE_PROMPT` is shared and defined once in `training_configs/__init__.py`.

Scores are 0–100 from the judge; coherence is judged separately with the same scale.

### The cycle loop (`src/training/train_n_cycles.py`)
`run_iterative_training()` is the core and is imported directly by the sweep scripts (not shelled out). Per cycle:
- Cycle 0 trains a fresh rank-16 LoRA on the first `firstn` seed examples.
- Cycles 1+ sample the previous checkpoint on a disjoint partition of `QUERIES_FILE`, optionally rejection-sample on coherence via an OpenRouter labeling model, mix in `num_original_mix` seed examples, and train `num_training_examples` (`nte`) examples. By default each cycle re-initializes from the base model; `--init-n-minus-1` / `chain_from_prev` continues from the previous cycle's saved training state (this "continual" variant is where amplification actually shows up in the paper).
- Each `cycle<N>/` dir gets `log.txt` (tinker sampler path), `state_log.txt` (tinker training-state path, only when chaining), `training_data*.jsonl`, and `done.txt`. `experiment_summary.json` at the run root is rewritten after every cycle and is what eval scripts consume. **Resumption is driven by `done.txt` + `log.txt`**: re-running the same output dir skips finished cycles.
- Renderer choice is by model name (`utils/renderer_utils.py`: llama→llama3, qwen→qwen3, deepseek→deepseekv3). LR schedule is shared across all trainers via `training/lr_schedules.py`.

`src/train_n_cycles.py`, `src/eval_w_retries.py`, and `training/legacy_train_n_cycles.py` are older copies kept for `mega_sweep.py`; new work goes in `src/training/`.

### Sweeps and calibration
`src/sweep/sweep.py` grids `firstn × nte` into `<output-root>/seed<firstn>_nte<nte>/`, running each via `ProcessPoolExecutor` (`--parallel`). Unless `--firstn` is given, it first runs **calibration** (`sweep/calibrate.py`): binary-search the cycle-0 `firstn` that reaches each score threshold in `EVAL_THRESHOLDS`, cache results and cycle-0 checkpoints under `cache/calibration_<config>_<model>_<schedule>/calibration_results.json`, and use those firstn values as the grid (cycle 0 is then reused from cache rather than retrained). DPO sweeps use `beta<β>_nte<N>` / `beta<β>_steps<N>` / `beta<β>_lr<x>_bs<N>` run names; `eval_sweep.py` and `plotting/sweep_plot_utils.parse_run_name` recognize all of these patterns, so any new run-name scheme must be added in both places.

### Evaluation
`evaluation/eval.py` exposes `evaluate_model_score(...)` (instruct models) and `evaluate_model_score_sdf(...)` (base models, prefix completion) which everything else builds on. Judge scoring uses logprob-weighted numeric aggregation over GPT-4o outputs. `eval_sweep.py` reads each run's `experiment_summary.json` (falling back to `cycle*/log.txt`) and writes `eval_results.json` per run. Secondary metrics live alongside: `compute_perplexity.py` / `bucket_perplexity.py` (updates eval JSON in place), `eval_branching_factor.py`, `eval_token_freqs.py`.

### Data
- `datasets/sft/<trait>/` — seed SFT sets as `{"messages": [...]}` jsonl, produced by `generate_<trait>.py` scripts that share `datasets/sft/tinker_generator.py` or `openai_generator.py`. `datasets/sft/test_data/` holds held-out high/low perplexity buckets.
- `datasets/sdf/` — synthetic documents for continued pretraining, generated by `generate_documents.py --persona ...` (the paper's final files are listed in `datasets/sdf/REPRODUCIBILITY.md`).
- `src/data/` — prompt pools used during cycles 1+ (`dilemmas.json`, `lmsys_queries.json`, `open_ended_alt.json`, `prompt_prefixes.json` for SDF). `paths.py` exposes `REPO_DIR`, `DATA_DIR`, `SDF_DIR`.

### Post-hoc analysis
`src/analyses/detect_amplification.py` classifies runs as amplified (delta / prefix-regression / late-delta methods); `src/scripts/generate_seed_sweep_jobs.py` and `replicate_amplified_sweep.py` then generate SLURM jobs to replicate amplified runs across seeds. Plots in `src/plotting/` are per-figure scripts sharing `sweep_plot_utils.py` (font sizes, axis labels like $n_{seed}$ / $n_{sampled}$).
